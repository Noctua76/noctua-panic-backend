# Physical Android/PWA acceptance procedure — prepared, not executed

Owner-dependent prerequisite: a real trusted device and a separately authorized isolated synthetic deployment. Current production still runs the accepted old mains; do not sideload a candidate into a real dispatch environment or press a production panic button under this procedure. Any real alert/SMS/voice acceptance requires its own explicit authorization.

Record content-free evidence: date/operator, device model, Android/Chrome versions, install mode, network state, candidate source/build IDs, active worker/controller/runtime version and case PASS/FAIL/recovery code. Use only synthetic companies/Guards/incidents/answers and synthetic dispatch adapters. Never export browser bearer tokens, real answers/SOPs, key material, phone numbers or operational screenshots.

| Case | Device steps | Required evidence/result |
|---|---|---|
| D01 Build/controller identity | Open installed PWA and already-open tab; record runtime/index/worker/controller IDs. | All match approved candidate after controlled transition; old pages identified, not assumed updated. |
| D02 Concurrent flows | Trigger two synthetic incidents; leave first incomplete, complete second. | Independent version/timer/answers; only current-session completed flow clears; synthetic dispatch count exact. |
| D03 Online restart | Type unique synthetic canary, wait for LOCALLY_SEALED then server custody; force-close/reopen. | Same original session recovers exact content; no stored plaintext/private key. |
| D04 Offline active page | Disconnect while editing in an already unlocked page. | Sealed checkpoints persist with cached public key; accurate local-versus-server status; no plaintext fallback. |
| D05 Offline cold restart | Restart while disconnected, then reconnect. | No recovered plaintext until online original-session authorization. Network-only shell may be unavailable offline; ciphertext remains. |
| D06 Lock/sleep/network handover | Lock/sleep at least 5 minutes, switch Wi-Fi/mobile, resume after background eviction. | No session reassignment, stale callback or silent loss; recoverable state and original encrypted packet retained. |
| D07 Quota/storage failure | On a controlled synthetic build, inject IndexedDB quota failure (do not fill/wipe a personal device). Request worker/client reload. | RAM_ONLY warning, no durability claim, transition blocked until seal succeeds; no plaintext fallback. |
| D08 Legacy migration interruption | Inventory original-session legacy drafts, interrupt upload/receipt, reopen, retry. | Plaintext stays until custody plus authenticated readback match; only that verified record is removed. No blanket clear or fabricated snapshot. |
| D09 Session/Preview boundary | Switch A -> B, same Guard later session, then read-only Preview, including a pending old response. | A's UI/RAM cleared; original ciphertext kept; B/Preview cannot read/submit A; current alert state unaffected. |
| D10 Receipt loss/resolution | Lose final receipt after synthetic commit; resolve incident; retry/restart. | Exact original receipt, one canonical fact set, no duplicate dispatch or fabricated first finalization. |
| D11 Mixed generations | Keep old PWA open against new backend/default and custom; new client against isolated old backend; then restore approved floor. | Compatible three aliases only; custom gives 409 UPGRADE_REQUIRED; new sealed data retained on old backend; floor reads old/new facts with old keys. |
| D12 Worker update and disclosure | Initiate candidate worker update with pending alert/local write; inspect localStorage, IndexedDB, CacheStorage, console and network canaries. | Wait for pending work; no forced reload on quota failure; no content/token/URL leakage to logs/cache/unauthorized domains. |

On failure: stop that device's activation, preserve ciphertext and content-free diagnostics, record exact failing case/build/state, restore connectivity or correct the scoped defect, retest the case and affected adjacent flows. Do not clear storage, reassign identity or roll back to pre-engine readers. No new live alert is a diagnostic retry.

Acceptance is recorded by the Owner/device operator and independently reviewed against the exact source and test manifest. Synthetic Chromium success is prior supporting evidence, not a physical Android result. Until this sheet is executed, device acceptance remains NOT EXECUTED, a genuine physical-access/release-authorization gate.
